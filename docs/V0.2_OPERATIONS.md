# V0.2 local deployment and API contract

## Install

From the repository root:

    pip install -e ".[dev]"
    pip install -e "./backend[dev]"
    export DASHSCOPE_API_KEY="your-key"
    cd backend
    uvicorn app.main:app --host 127.0.0.1 --port 8000

In another terminal:

    cd frontend
    npm ci
    npm run dev

## API

- POST /api/papers/upload: multipart/form-data PDF, returns 202 with paper_id/job_id/status.
- POST /api/papers: JSON {"source":"2301.12345"} (arXiv ID / arxiv.org URL).
- GET /api/papers: list of paper statuses.
- GET /api/jobs/{job_id}: durable job status.
- GET /api/jobs/{job_id}/events: immutable task events.
- POST /api/jobs/{job_id}/retry: retry a FAILED_RETRYABLE job.
- POST /api/jobs/{job_id}/cancel: cooperative cancellation.
- GET /api/papers/{paper_id}/mindmap: normalized mind map (READY only).
- GET /api/papers/{paper_id}/artifacts/xmind: XMind binary download.
- GET /api/papers/{paper_id}/source: original source PDF (READY only).

## Operational boundaries

Single local worker with SQLite WAL. Do not expose on public interfaces without
authentication and resource isolation. Cancellation is cooperative between pipeline
stages and does not interrupt a currently running model call. Failed transient jobs
retry at most 3 times with backoff. Scanner-only PDFs without extractable text fail
closed, because OCR is deferred to V0.3.

Persistent state resides in the configured DATA_DIR, including paper2xmind.sqlite3,
papers and uploads. The worker can reclaim expired RUNNING leases after process
restart. Use SQLite online backup API for a live database backup rather than simply
copying the WAL. Do not use multiple worker processes in V0.2.

Offline tests use mocked LLM behavior; production smoke tests need an API key,
and a generated XMind file must additionally be opened in the XMind application.
